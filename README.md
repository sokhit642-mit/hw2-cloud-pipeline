# CI/CD with Jenkins, GitHub, Docker & Docker Swarm on AWS

## 1. Project Overview
This project delivers a fully automated Continuous Integration and Continuous Deployment (CI/CD) pipeline on Amazon Web Services (AWS). It establishes an automated path from a code commit on GitHub to a zero-downtime rolling deployment across a distributed Docker Swarm cluster.

### Pipeline Workflow
1. **Developer Push:** A code change is committed and pushed to the `main` branch of this GitHub repository.
2. **Automated Trigger:** Jenkins polls the GitHub repository every minute (`* * * * *`) and automatically triggers a build upon detecting new commits.
3. **Container Build & Tagging:** Jenkins builds the production Docker image using an Alpine-based Nginx server, tagging it with the sequential build number (`v${BUILD_NUMBER}`) and the `:latest` reference.
4. **Artifact Storage (Amazon ECR):** Jenkins logs in to Amazon Elastic Container Registry (ECR) via a transient `amazon/aws-cli` container and pushes the newly tagged image.
5. **Swarm Rolling Deployment:** Jenkins connects via SSH to the AWS EC2 Docker Swarm Manager node, executing a service update with the `--with-registry-auth` flag.
6. **Cluster Rollout:** Docker Swarm distributes the new image to worker nodes and performs a zero-downtime rolling update across all running task replicas.

## 4. How to Run Locally

To test and verify the containerized application on a local development machine:

1. Clone the repository:
   git clone https://github.com/sokhit642-mit/hw2-cloud-pipeline.git
   cd hw2-cloud-pipeline

2. Build the Docker image:
   docker build -t my-app:local .

3. Run the container locally:
   docker run -d -p 80:80 --name local-web my-app:local

4. Verify local execution:
   Open a browser and navigate to `http://localhost` to confirm the application serves properly.

5. Stop and clean up the test container:
   docker rm -f local-web

## 5. How to Deploy to AWS Docker Swarm

### Step 1: Initialize the Swarm Cluster
On the Manager EC2 instance (32.236.227.255):
docker swarm init --advertise-addr 172.31.39.60

### Step 2: Join the Worker Node
On the Worker EC2 instance (13.210.39.69), execute the join token generated by the manager:
docker swarm join --token <SWARM_WORKER_TOKEN> 172.31.39.60:2377

### Step 3: Deploy the Stack
On the Manager EC2 instance, authenticate with Amazon ECR and deploy the stack:
aws ecr get-login-password --region ap-southeast-2 | docker login --username AWS --password-stdin 251528148716.dkr.ecr.ap-southeast-2.amazonaws.com
docker stack deploy --with-registry-auth -c docker-stack.yml my-stack

## 7. Security Best Practices Implemented
- **No Hardcoded Credentials:** AWS access keys and SSH private keys are strictly managed via Jenkins credentials and never committed to version control.
- **Decoupled AWS CLI Dependency:** ECR authentication runs within an on-demand `amazon/aws-cli` container, eliminating host-level tool dependencies.
- **Secure Cluster Credential Sharing:** The `--with-registry-auth` flag passes short-lived registry authorization tokens securely over the encrypted Swarm overlay network to worker nodes.
